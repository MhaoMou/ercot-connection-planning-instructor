# ACTIVSg2000 scenario package

The production game uses the public synthetic Texas ACTIVSg2000 model and a
controlled three-year scenario package labeled as instructional years
2027--2029. These labels are not historical source-data years or forecasts.

This document describes the hourly source package
(`data/processed/activsg2000_scenarios_v1`), which is built locally and is not
published in this repository. The canonical classroom release is
the six-hour package `data/processed/activsg2000_scenarios_v2_6h`, built from
the hourly package by `tools/activsg2000/build_aggregated_scenario_package.py`
(`--source-dir` the hourly package, `--output-dir` the six-hour package). Each
six-hour game period is the mean of six consecutive source hours, giving 724
(January--June 2027/2029), 728 (January--June 2028), or 736 (July--December)
periods per block; all six blocks of the six-hour package report
`validation_status: passed`.

## Package

The package is generated by:

    PYTHONPATH=src python tools/activsg2000/build_scenario_package.py \
      --source-dir path/to/ACTIVSg2000 \
      --output-dir data/processed/activsg2000_scenarios_v1

It contains:

    data/processed/activsg2000_scenarios_v1/
      manifest.json
      profile_parameters.json
      network/
      2027/jan_jun/
      2027/jul_dec/
      2028/jan_jun/
      2028/jul_dec/
      2029/jan_jun/
      2029/jul_dec/

The source topology is fixed at 2,000 buses, 3,206 branches, and 544
generators. Each block exposes the catalog files required by the CSV checker.
Hourly demand is generated deterministically from the profile recipe, so the
repository does not need to store hundreds of millions of repeated CSV cells.
The active release uses the dataset's static generator status, PMIN, and PMAX
limits. ACTIVSg2000 does not provide generator technology labels or hourly
availability data, so no synthetic wind/solar derating is applied.

## Scenario construction

Bus demand starts from the ACTIVSg2000 bus PD values and uses a bounded
calendar-aware seasonal, daily, and weekly multiplier. Active generators use
their catalog status, PMIN, and PMAX values in every hour. Generator marginal
costs and branch limits are copied from the public ACTIVSg2000 files.

This is a controlled instructional scenario package. 2028 is the leap-year
calendar block; 2027 and 2029 are non-leap-year blocks. It is not historical
ERCOT telemetry, an official ERCOT model, or a forecast.

## Hourly validation

Full six-block DCOPF validation is pending in this environment: the optional
`highspy` dependency is unavailable, so the checked-in root and block manifests
are explicitly `validation_status: unverified_dependency`. This is not a
successful validation claim, and the evaluator fails closed until a complete
HiGHS-backed run succeeds.

Before a block can be used, install `highspy` and run:

    PYTHONPATH=/path/to/highspy:.:src python3 \
      tools/activsg2000/validate_scenario_package.py \
      --package data/processed/activsg2000_scenarios_v1

The validator materializes all 26,304 hourly states, solves a DCOPF for each
state, records failed periods, and changes the root and block manifests to
`validation_status: passed` only if every state is feasible. A missing-`highspy`
runtime error remains `unverified_dependency` rather than becoming a generic
solver failure. The evaluator fails closed when a block manifest is missing or
not passed.

A partial smoke run can be requested with --max-hours, but it never produces
a usable production manifest.

The released half-year horizons are 4,344 hours for January--June in
non-leap years (2027 and 2029), 4,368 hours for January--June in the leap year
2028, and 4,416 hours for July--December in every released year.
