# IT-service value profile

**Status:** Historical first-release policy, superseded. The current game
uses a constant $6,500/MWh IT value over six-hour periods (724, 728, or 736
values per half-year) in
`data/teaching/dispatch_scoring_rules_{jan_jun,jul_dec}_6h_v1.json`; those rule
files are authoritative. The hourly values below describe the retired release.

The evaluator assigns a value to served computational load. This is an
instructor-chosen **opportunity value of IT service**, not an electricity
market price and not a claim about a cloud provider's production economics.

## Current release

All released half-year blocks use the same explicit AI-intensive full-horizon policy:

```text
IT_value[t] = 1,500.00 USD/MWh,  for every hour t
```

| Rule file | Horizon | IT-value entries |
|---|---:|---:|
| 2027/2029 January--June | 4,344 hours | 4,344 values |
| 2028 January--June | 4,368 hours | 4,368 values |
| 2027/2028/2029 July--December | 4,416 hours | 4,416 values |

The vector is intentionally explicit and constant rather than a six-hour pattern. A
constant vector is easier for students to audit, avoids unexplained periodicity,
and makes strategic time variation come from the network operating state, load,
the validated hourly scenario and the released hourly energy-price surface.
The selected scenario block's economic-profile manifest is authoritative for the
actual horizon; the evaluator does not assume that every January--June block has
the leap-year length.

## Provenance and reproducibility

- **Source category:** `INSTRUCTOR-CHOSEN`.
- **Profile name:** `AI-intensive`.
- **Profile version:** `it-service-value-v3-ai-intensive`.
- **Units:** USD per MWh of served computational load.
- **Representation:** explicit full-horizon profile generated by
  `tools/activsg2000/build_economic_profiles.py`.
- **Determinism:** given the horizon and base value, regeneration produces the
  same vector.

The profile is not derived from the ACTIVSg2000 generator-cost table. Existing
generator operating costs remain dataset-specified, while the IT-service value
is a separate scoring assumption.

## Future extensions

Any replacement must provide one value for every hour, document its source or
instructor rationale, record units/version/hash, pass positivity and
deterministic-regeneration tests, and be announced before student submission.
No future profile should silently restore a repeated six-value template.
