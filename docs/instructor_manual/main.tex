\section{Instructor overview}

Each group represents a data-center operator. A group chooses connection sites,
site capacities, optional private generation, and optional private storage. The
instructor collects one canonical site-level CSV per group and evaluates the
submissions jointly with a fixed-load DC optimal power flow (\code{DCOPF}).
Groups are ranked by their final score.

Students are explicitly encouraged to use AI tools, including ChatGPT, Codex,
Claude Code, GitHub Copilot, and similar systems. The instructor should grade
the submitted artifact and the students' engineering explanation, not whether
students manually typed every line of code. Students remain responsible for
validating generated code and understanding their plan.

The recommended production workflow is:
\begin{center}
\fbox{\parbox{0.84\textwidth}{\centering
ACTIVSg2000 public model\\
$\Downarrow$\\
Scenario block and hourly economic artifacts, subject to validation gate\\
$\Downarrow$\\
Student CSV collection and format validation\\
$\Downarrow$\\
Joint DCOPF evaluation and fair continuous projection\\
$\Downarrow$\\
Scores, diagnostics, and protected classroom reporting
}}
\end{center}

\section{Production mental model}

The release uses the following distinction:
\begin{itemize}[leftmargin=*]
  \item \textbf{Public dataset:} the synthetic Texas ACTIVSg2000 topology,
  buses, branches, generators, status values, PMIN, PMAX, and marginal costs.
  \item \textbf{Derived scenario:} deterministic bus-level hourly load profiles
  over six released half-year blocks, grouped into three weekly matches.
  \item \textbf{Instructional assumptions:} student-owned assets, IT value,
  capital costs, storage costs, DCOPF settlement, scoring, and fair projection.
\end{itemize}

The active scenario package contains 2,000 buses, 3,206 branches, and 544
generator records. ACTIVSg2000 does not provide technology labels or hourly
availability fields. Therefore the active release uses each active generator's
dataset status, PMIN, and PMAX in every hour; it does not apply synthetic
wind/solar derating. The package is not historical ERCOT telemetry, an official
ERCOT planning model, or a forecast.

Team-built resources follow a separate convention. A team's \code{bus\_id} must
refer to a public bus in the selected scenario block. The canonical CSV submits
generator and storage capacities directly; it does not select an existing public
generator or storage device by ID. Every team-built generator uses the same
convex piecewise-linear
operating curve at every bus: 25\% of capacity at \$60/MWh, the next 50\% at
\$100/MWh, and the final 25\% at \$160/MWh. Students submit capacities; the
evaluator determines hourly dispatch. Team-built generators and storage serve only
their submitting team.

Accepted sites, evaluator-assigned assets, and final storage SOC persist from
Submission 1 to Submission 2 within a week. Generator, storage, and newly
built connection capital is charged once in that weekly match. The asset ledger
and SOC reset at the beginning of the next week.

The released artifacts are under
\path{data/processed/activsg2000_scenarios_v1/<year>/<block>}. The root and
block manifests record validation status, scenario hashes, and artifact
metadata. In this checkout, all six blocks are
\code{validation\_status: unverified\_dependency} because \code{highspy} is
unavailable. This is a dependency limitation, not a passed or failed validation.
A block must report \code{validation\_status: passed} after a complete
HiGHS-backed run before it is used for a classroom round.

\section{Student submission contract}

The active CSV header is exactly seven columns:
\begin{lstlisting}
team_id,site_id,bus_id,connection_capacity_mw,generator_capacity_mw,storage_power_mw,storage_energy_mwh
\end{lstlisting}

The file has one data row per site and no hourly horizon rows. It has no
\code{period}, hourly \code{load\_mw}, \code{submission\_id},
\code{generator\_id}, or \code{storage\_id} columns. \code{site\_id} is a
team-defined site label; \code{bus\_id} must come from the selected block's bus
catalog. The evaluator uses the submitted site capacities with the released
hourly scenario and applies the common team-built generator curve described
above. It assigns deterministic private generator and storage IDs from the
team/site identity. Students do not submit those IDs. Generator and storage
assets are private to the submitting team and cannot serve another team.

Example:
\begin{lstlisting}
team_id,site_id,bus_id,connection_capacity_mw,generator_capacity_mw,storage_power_mw,storage_energy_mwh
team-blue,site-north,1001,40,20,10,40
team-blue,site-south,1002,15,0,0,0
\end{lstlisting}

The retired ten-column hourly format is historical compatibility input only.
Do not distribute it as a current student template.

Students submit storage capacities only. The grid operator schedules storage in
the centralized prepared HiGHS model. Storage uses MW power capacity and MWh
energy capacity. With ideal charging and discharging efficiency, the evaluator
enforces power and energy bounds, binary no-simultaneous charge/discharge,
discharge no greater than the stored energy, an initial state of charge of
$0.5B$, and a terminal state of charge of at least $0.5B$. Discharge can reduce
only the owning team's load.

\section{Course operation}

Before Week 1, provide students with the student handout, the active scenario
package, the CSV checker, and the bus catalog. Collect two submissions per week
for the three weekly matches. The instructor should record the week, submission
number, year/block, deadline, submission directory, rule-file version, and a
hash of each frozen input directory.

Recommended sequence:
\begin{enumerate}[leftmargin=*]
  \item Explain the data/model distinction and the CSV contract.
  \item Give groups time to explore candidate buses and resource portfolios.
  \item Require each group to run the checker before submission.
  \item Freeze the submission directory at the deadline.
  \item Run the batch evaluator once for each submission, or run the classroom
  coordinator for the complete six-submission prefix.
  \item Release Week 1 feedback and privacy-safe aggregate/team summaries
  without exposing competitors' private plans.
\end{enumerate}

\section{Instructor command cookbook}

Check one submission:
\begin{lstlisting}
ercot-game-check-csv --file path/to/team.csv
\end{lstlisting}

Evaluate a frozen round:
\begin{lstlisting}
ercot-game-batch run \
  --submissions-dir work/round_01/submissions \
  --artifact-dir data/processed/activsg2000_scenarios_v1/2028/jan_jun \
  --rules data/teaching/dispatch_scoring_rules_jan_jun_v1.json \
  --year 2028 --round jan_jun \
  --submission-number 2 \
  --workers 8 --projection-iterations 10 \
  --output-dir work/round_01/results
\end{lstlisting}

The submission number is evaluator-side metadata, not a CSV column. The CLI
accepts \code{1} or \code{2} and defaults explicitly to \code{2}. Use
\clioption{--submission-number 1} for a practice run: it excludes energy-purchase
cost while retaining the other active scoring terms. Use
\clioption{--submission-number 2} for the scored run, which settles grid purchases
at the locational marginal price (LMP) from the selected joint dispatch.
Submission 1 is practice and has no energy-purchase cost while retaining the
other active scoring terms.

For an end-to-end classroom run, provide a manifest containing the six released
rounds and use:
\begin{lstlisting}
ercot-game-batch classroom \\
  --manifest work/classroom_manifest.json \\
  --state-path work/classroom_state.json \\
  --output-dir work/classroom_results
\end{lstlisting}

The classroom coordinator rejects a second submission without a committed first
submission for that week, persists the asset ledger and SOC within the week,
resets them between weeks, and writes aggregate classroom-safe outputs.

Validate the complete scenario package:
\begin{lstlisting}
PYTHONPATH=.:src python3 tools/activsg2000/validate_scenario_package.py \
  --package data/processed/activsg2000_scenarios_v1 --workers 6
\end{lstlisting}

The economic profiles are generated by the module invocation below. The
module form is intentional because the builder uses package-relative imports:
\begin{lstlisting}
PYTHONPATH=.:src python3 -m tools.activsg2000.build_economic_profiles \
  --artifact-dir data/processed/activsg2000_scenarios_v1/2028/jan_jun \
  --output-dir data/processed/activsg2000_scenarios_v1/2028/jan_jun
\end{lstlisting}

\section{Evaluation and joint infeasibility}

Malformed files are rejected independently so that valid teams remain eligible
for evaluation. A valid plan may be feasible alone but infeasible when all
teams are dispatched together. Before projection, the evaluator caps each site
at $100\MW$, each team at $500\MW$, and in multi-team cases caps the largest
request at the smallest positive team request. It then chooses a separate
$\alpha_i\in[0,1]$ for each team: first maximize total served load, then within
$\max(10^{-6},10^{-6}L^*)$ MWh of the optimum maximize
$\sum_i\log(\alpha_i d_i)$. The output records each team's service fraction,
projected load, cap policy, projection scope, and proportional-fair utility.
Submitted asset costs remain part of the score, while served-load value and
energy costs reflect the projected load.

If a projected dispatch cannot be found, the evaluator records
deterministic leave-one-team-out and individual fallback attempts where
possible. This prevents one invalid or excessively large submission from
silently erasing the scores of otherwise valid teams.

\section{Scoring model}

At a high level, a team's score is:
\begin{align*}
\text{IT value}
&-\text{energy purchase cost}
-\text{generator operating cost}
-\text{generator capital cost}
\\
&-\text{storage capital cost}
-\text{site cost}.
\end{align*}

The active instructional coefficients are IT value of \USD1500/MWh, a
team-built generator curve of \$60/\$100/\$160 per MWh at 25/50/25\%, site
cost of \USD20m/MW, generator capital cost of \USD1.3m/MW, and storage capital
costs of \USD350,000/MW plus \USD200,000/MWh. A four-hour storage device
therefore has a \USD1.15m/MW capital equivalent, and storage operating cost is
not charged. The site coefficient is an instructor-chosen mapping informed by
JLL shell/core and AI fit-out construction costs~\cite{jll2026dc}; EIA/NREL
technology and battery benchmarks inform generator and storage calibration~\cite{eia2024generatorcosts,eia2025heatrate,nrel2024bess,eia2024bess}.

For Submission 2, energy purchase cost uses the nonnegative LMP from the
selected joint dispatch at the selected bus and hour. The released LMP
artifacts are deterministic economic-profile references with one row per hour
and one column per bus; raw balance duals are retained for audit. Submission 1
is practice and has no energy-purchase cost. IT value is a complete
full-horizon vector supplied in the corresponding economic-profile JSON. These
are instructional model outputs, not official ERCOT market prices. The
submission number is selected on the instructor CLI and is never represented by
an extra CSV column.

\section{Privacy and classroom reporting}

Keep raw CSVs, per-team diagnostics, bus selections, generator capacities,
storage capacities, and hourly profiles instructor-only. The classroom writer's
shared \code{classroom-safe-v1} output may include aggregate team counts,
aggregate periods, and aggregate projection metadata. Each team receives only
its own \code{classroom-private-v1} summary under a hashed directory, with its
own score and scalar diagnostics. Never publish a map or raw JSON that lets one
group reconstruct another group's exact sites or resource portfolio.

\section{Reproducibility and release audit}

Before release, verify:
\begin{itemize}[leftmargin=*]
  \item all six scenario blocks report a passed validation manifest; if
  \code{highspy} is unavailable, record \code{unverified\_dependency} and do
  not release the block;
  \item every economic-profile NPZ hash matches its manifest;
  \item the chosen rule file and scenario block match the round announcement;
  \item a dry-run CSV passes the checker and batch evaluator;
  \item the output directory contains the leaderboard, manifest, evaluation
  record, diagnostics, and hashes;
  \item the frozen submission directory is archived before any feedback is released.
  \item the Colab benchmark has a completed full-horizon result before making
  any performance or horizon-reduction claim; the benchmark requires
  \code{highspy}, \code{psutil}, prepared artifacts, and a compatible runtime.
\end{itemize}

\section{Troubleshooting}

\begin{description}[leftmargin=2.2cm,style=nextline]
  \item[Malformed CSV] Run the checker and return the error to the CSV-format
  section of the student handout. Do not repair a student's file silently.
  \item[Unknown bus] Confirm that the \code{bus\_id} comes from the selected
  half-year artifact, not from a retired prototype.
  \item[Duplicate site] Ensure that every canonical data row has a distinct
  \code{site\_id}.
  \item[Joint infeasibility] Inspect projection metadata and binding diagnostics.
  A valid team may still receive a projected score.
  \item[Missing economic profile] Confirm that the selected block contains all
  of the following files and that the manifest hash matches:
  \begin{itemize}[leftmargin=*]
    \item \code{economic\_profiles.npz}
    \item \code{economic\_profile.json}
    \item the block manifest
  \end{itemize}
\end{description}

\section{Instructor checklist}

\begin{enumerate}[leftmargin=*]
  \item Select the three-week schedule, submission number, rule file, and deadlines.
  \item Publish the student handout and checker.
  \item Freeze and hash the submission directory.
  \item Run format validation and the full batch evaluation for each submission,
  or run the classroom coordinator.
  \item Confirm weekly persistence, one-time capital charges, and reset at the
  start of Weeks 2 and 3.
  \item Inspect valid/invalid counts, per-team projection scope, and diagnostics.
  \item Release protected summaries and retain the complete instructor archive.
\end{enumerate}
