# Hyperparameters and configuration

**Status:** Current repository configuration; instructor review required before student release.

This file is the compact reference for the numerical and behavioral choices used
by the ACTIVSg2000-based dispatch game. Each setting is labeled as one of:

- **DATASET-SPECIFIED** — copied from, or directly determined by, the canonical ACTIVSg2000 source package.
- **ONLINE-SOURCE CALIBRATED** — anchored to a public market, engineering, or cost reference and then rounded or mapped into the game.
- **INSTRUCTOR-CHOSEN** — selected for learning objectives, reproducibility, computational tractability, or the student interface.

These labels describe the source of a game setting. They do not mean that any
value is an official ERCOT operating parameter.

## Model hierarchy

    ACTIVSg2000 source model
      buses, branches, generators, costs, and source demand
                         |
                         v
    Instructor game configuration
      half-year calendar, teaching profiles, ownership, scoring
                         |
                         v
    Student CSV submissions
                         |
                         v
    One-hour linear DCOPF evaluation and score

The game uses the ACTIVSg2000 network directly as the dispatch network. It does not
use the earlier toy webpage network or the retired six-period submission
convention.

## Economic and scoring parameters

For a valid team, the score is:

    score = IT-service value
          - energy purchase cost
          - generator operating cost
          - generator capital cost
          - connection-site cost
          - storage capital cost

Hourly quantities are multiplied by the one-hour time step.

| Parameter | Current value | Source category | Applied as |
|---|---:|---|---|
| IT-service value | 1,500 $/MWh at every hour; AI-intensive profile | **INSTRUCTOR-CHOSEN** | Value of served data-center load; explicit full-horizon vector |
| Energy purchase price | Submission 1: excluded; Submission 2: LMP from the joint dispatch at each selected bus | **DATASET-SPECIFIED + DERIVED** | Locational cost of net grid energy purchased |
| Existing-generator operating cost | Dataset marginal_cost_c1_per_mwh | **DATASET-SPECIFIED** | Cost of dispatching a selected existing generator |
| Team-built generator operating curve | 25% at $60/MWh, 50% at $100/MWh, 25% at $160/MWh | **INSTRUCTOR-CHOSEN** | Same convex curve for every team-built generator and site |
| Student generator capital cost | $1,300,000/MW | **INSTRUCTOR-CHOSEN** | One-time cost per newly built generator MW in a weekly match |
| Connection-site cost | $20,000,000/MW of newly built connection capacity | **INSTRUCTOR-CHOSEN** | Capacity-dependent one-time connection cost |
| Storage power capital cost | $350,000/MW | **INSTRUCTOR-CHOSEN** | One-time cost for newly built storage power capacity |
| Storage energy capital cost | $200,000/MWh | **INSTRUCTOR-CHOSEN** | One-time cost for newly built storage energy capacity; four-hour total is $1.15m/MW |
| Storage operating cost | Not charged | **INSTRUCTOR-CHOSEN** | Storage is operated by the grid optimizer without a variable operating-cost term |
| Infeasible score | 0 | **INSTRUCTOR-CHOSEN** | Score when no feasible projected/fallback dispatch exists |
| Curtailed energy | Not used | **INSTRUCTOR-CHOSEN** | No load-shedding or curtailment recourse; centralized storage still uses binary operating-mode variables |

The generator-capital coefficient is an approved instructional value. The
storage split is an approved four-hour relation totaling $1,150/kW. Storage
operating cost is not charged.

The legacy schema field default_generator_cost_per_mwh = 100 remains only for
backwards-compatible parsing. It is not the production operating cost for a
team-built generator. Team-built generator IDs are evaluator-derived private
labels based on the submitting team and site; students do not submit a public
generator-catalog ID. Existing public generators, when used by the dispatch
model, retain their dataset-defined costs; they are distinct from team-built
generators.

## Storage operating constraints

Storage is ideal: charging and discharging have 100% efficiency. Students
submit capacities. In prepared-artifact evaluation, the evaluator solves one
centralized multi-period binary MIP with HiGHS: each storage asset has a binary
operating-mode variable that prevents simultaneous positive charging and
discharging. The legacy compatibility path without a prepared artifact uses a
deterministic continuous peak-shaving schedule instead; that path is not the
centralized classroom dispatch model.

For asset j, with power P, energy B, state e, charging c, and discharging d:

    0 <= c[t] <= P
    0 <= d[t] <= P
    e[t+1] = e[t] + (c[t] - d[t]) * time_step_hours
    0 <= e[t] <= B
    e[0] = 0.5 * B
    e[T] >= 0.5 * B
    d[t] * time_step_hours <= e[t]

The schedule does not intentionally charge and discharge the same asset in the
same hour. Discharge reduces only its owner's net load and cannot export to
another team. Storage operating cost is charged on discharged MWh.

## Feasibility, projection, and batch evaluation

| Setting | Current value | Source category | Meaning |
|---|---:|---|---|
| Dispatch feasibility | Fixed-load DCOPF satisfies generator, balance, and branch limits | **INSTRUCTOR-CHOSEN** | No load shedding or curtailment variables |
| Joint infeasibility response | Fair continuous projection | **INSTRUCTOR-CHOSEN** | Valid teams share one common service fraction |
| Projection fraction | Largest feasible alpha in [0,1] | **INSTRUCTOR-CHOSEN** | Equal proportional service level |
| Projection tolerance | 1e-6 | **INSTRUCTOR-CHOSEN** | Bisection stopping tolerance |
| Minimum positive service fraction | 1e-6 | **INSTRUCTOR-CHOSEN** | Explicit positive-service endpoint |
| Requested projection iterations | Default 10 | **INSTRUCTOR-CHOSEN** | CLI lower bound |
| Effective minimum iterations | 20 | **INSTRUCTOR-CHOSEN** | Required to resolve the 1e-6 tolerance |
| Malformed-file handling | Reject that file; continue valid files | **INSTRUCTOR-CHOSEN** | Isolates independent teams |
| Dispatch-failure fallback | Deterministic leave-one-team-out / individual evaluation where applicable | **INSTRUCTOR-CHOSEN** | Recoverable evaluation path |
| Result ordering | Deterministic | **INSTRUCTOR-CHOSEN** | Repeated inputs give stable output ordering |

Projection is instructor-side policy, not a student-controlled parameter. A
projected score uses projected load while retaining submitted asset costs, and
the batch output identifies the projection scope.

## What students can tune

Students choose canonical site-level plan variables: site IDs, catalog bus IDs,
connection capacities, generator capacities, and storage power and energy
capacities. The CSV has one row per site; students do not submit hourly load,
generator-ID, or storage-ID columns. The evaluator selects the hourly horizon
and derives private generator and storage asset IDs from each team/site pair.
Students do not choose prices,
IT values, network limits, generator marginal costs, projection tolerance, or
scoring coefficients.

## Review status and limitations

- Both active half-year rule files currently have status
  instructor_review_required.
- IT-service value is now a complete constant full-horizon vector; it is not a
  repeated six-hour profile.
- Energy-price settlement uses the immutable baseline ACTIVSg2000 DCOPF LMP
  artifacts included in each released half-year block.
- The canonical ACTIVSg2000 source is the fixed network source; the three-year
  operating package is a controlled generated scenario, not historical ERCOT
  operation.
- The active package does not apply synthetic wind/solar availability caps;
  generator status, PMIN, and PMAX are taken directly from ACTIVSg2000.
- Fixed storage O&M of approximately $40/kW-year is a reference benchmark only;
  the $8/MWh variable proxy is the charged operating cost.
